# IOM 诊断 Agent 治理宪章

## 1. 治理原则

本插件严格遵循以下治理机制，确保诊断过程可追溯、可验证、用户可控。

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **流程驱动** | G0–G5 阶段门控制，不通过不进入下一阶段 |
| **治理为先** | 所有输出必须经过阶段门验证 |
| **方法赋能** | 最小方法栈按需调用，禁止方法堆砌 |
| **用户决策** | 用户是唯一 VF（Verified & Frozen）授权者 |
| **可追溯闭环** | 证据/页面/门径三台账全留痕 |

### 1.2 IOM 特化原则

| 原则 | 说明 |
|------|------|
| **柔性约束** | 所有方案必须满足"设备 + 人员 + 产线"三柔性特征 |
| **财务锚定** | 所有 Finding 必须折算为 OTIF/周转/人均产值/利润语言 |
| **端到端** | 覆盖 Concept-to-Cash 全价值流，禁止局部优化 |

## 2. 阶段门机制（Stage Gates）

### G0–G5 阶段门定义

| Gate | 名称 | 准入条件 | 授权者 |
|------|------|----------|--------|
| **G0** | 界定 | Governing Question + 章程量化目标获用户确认 | 用户 |
| **G1** | 分解 | Issue Tree 通过 MECE 检查；假设矩阵覆盖四模块 | 用户 |
| **G2** | 证据 | 证据台账无 D 级关键证据；每个假设≥1 条 A/B 级证据或补证计划 | S4 审核 + 用户 |
| **G3** | 综合 | 逻辑审核 PASS；Finding→Insight→Implication 链完整；方案选择记录取舍 | 用户 |
| **G4** | 页面 | 章节 Review 通过；用户对页面显式批复 VF | **用户唯一** |
| **G5** | 交付 | deck 仅含 VF 页；review pack 含全链路留痕；gate_log 归档 | S6 自动校验 |

### 阶段门执行

```bash
# 检查指定阶段门
python skills/manage-iom-engagement/scripts/gate_check.py --gate G0

# 检查所有阶段门
python skills/manage-iom-engagement/scripts/gate_check.py --all
```

## 3. VF 机制（Verified & Frozen）

### 3.1 页面状态机

```
draft → confirmed → VF
```

- **draft**: 初始草稿状态，可自由修改
- **confirmed**: 内容已确认，等待用户 VF 授权
- **VF**: 已冻结，仅用户可撤销 VF 状态

### 3.2 VF 规则

1. **仅用户可授权 VF**：任何 Skill 不得自行将页面标记为 VF
2. **VF 后不可修改**：一旦页面进入 VF 状态，任何 Skill 不得修改其内容
3. **交付仅含 VF 页**：S6 produce-iom-deck 仅组装 VF 状态的页面

### 3.3 VF 授权记录

所有 VF 授权必须记录在 `state/page_register.md` 中，包含：
- 页面 ID
- VF 时间戳
- 用户批复原文引用

## 4. 台账规范（Registers）

### 4.1 证据台账（evidence_register.md）

| 字段 | 说明 |
|------|------|
| EV-ID | 证据唯一标识 |
| 来源 | 数据来源（客户系统/访谈/对标等） |
| 分级 | A/B/C/D（A=客户系统统计数据，D=假设待补证） |
| 支撑假设 | 关联的假设 ID |
| 时间戳 | 证据录入时间 |

### 4.2 页面台账（page_register.md）

| 字段 | 说明 |
|------|------|
| PG-ID | 页面唯一标识 |
| 章节 | 所属章节 |
| 状态 | draft/confirmed/VF |
| VF 批复原文引用 | 用户 VF 授权的原文记录 |

### 4.3 门径日志（gate_log.md）

| 字段 | 说明 |
|------|------|
| Gate | 阶段门编号（G0-G5） |
| 时间 | 检查时间 |
| 结果 | PASS/FAIL |
| 缺失项 | 未满足的准入条件 |
| 操作者 | 执行检查的角色 |

### 4.4 Storyline 台账（storyline.md）

| 字段 | 说明 |
|------|------|
| 版本 | Storyline 版本号 |
| 变更 | 变更内容描述 |
| 触发证据 | 导致变更的证据 EV-ID |

## 5. 红线（Red Lines）

以下行为被严格禁止：

1. **跳过阶段门**：未经 Gate 检查通过，不得进入下一阶段
2. **非用户 VF 授权**：任何 Skill 不得代替用户进行 VF 授权
3. **修改 VF 页面**：已 VF 的页面不得被任何 Skill 修改
4. **交付非 VF 页**：S6 不得将非 VF 页面纳入交付物
5. **方法堆砌**：方法栈不得超过 5 个方法
6. **无证据结论**：关键结论无 A/B 级证据支撑，逻辑审核必须 FAIL

---

## 6. 违规处理

- **自动拦截**：脚本检测到违规行为时自动拦截并告警
- **台账记录**：所有违规尝试记录在 gate_log.md
- **人工审查**：严重违规需人工审查后方可继续
